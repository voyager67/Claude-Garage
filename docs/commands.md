# Command reference

_Generated by `scripts/build-docs.py`. Commands are namespaced `/garage:<name>` when installed as a plugin and `/<name>` with the standalone installer._

## Setup

| Command | What it does | Argument |
|---|---|---|
| `/garage:garage-init` | One-time setup. Creates the .garage workspace, seeds lessons.md, detects the test command, and offers house rules plus an optional output style. | `` |
| `/garage:rules` | Create or update the project's house rules (guardrails) in .garage/rules.md through a short interview. The rules are checked automatically by blueprint, sprint, preflight and audit. | `[add <rule> | review]` |
| `/garage:guide` | Interactive command finder. Asks what you want to do, checks the state of your .garage workspace, recommends the right command and offers to start it. Use whenever you are unsure what to run. | `` |

## Understand

| Command | What it does | Argument |
|---|---|---|
| `/garage:recon` | Map an unfamiliar codebase in one page, including structure, entry points, how to run and test, conventions and gotchas. Use when joining or inheriting a project. | `[subdirectory or focus area]` |
| `/garage:patterns` | Discover the conventions and recurring patterns already in a codebase and turn them into documented patterns and suggested house rules. Use to learn how a team really writes code. | `[area, for example 'error handling' or 'api routes']` |
| `/garage:brainstorm` | Explore a fuzzy idea before committing to it. Generates conservative, ambitious and unconventional options, compares them and helps you pick one to pitch. | `<topic or problem>` |

## Plan

| Command | What it does | Argument |
|---|---|---|
| `/garage:pitch` | Turn a rough idea into a one-page pitch with target user, MVP scope, non-goals, success metric, kill criteria and a size (S, M or L) that picks the lane. Use before writing code for any new feature or product. | `<idea in one sentence> | <pitch id to resume>` |
| `/garage:blueprint` | Turn a pitch into a technical blueprint with trade-offs, interfaces, file-level changes and small build slices marked parallel-safe or not. For size L it also creates blind acceptance scenarios. Use after /pitch for M and L work. | `<pitch id, e.g. 001>` |
| `/garage:preflight` | Quality gate for a pitch and blueprint before building. Scores them for completeness, consistency and correctness (testability), and optionally checks house-rule compliance. Advisory, never blocking. | `<pitch id> [rules]` |

## Build

| Command | What it does | Argument |
|---|---|---|
| `/garage:sprint` | Execute a pitch or blueprint. Auto-detects the lane (S, M or L), runs up to three builders in parallel on disjoint slices, checks for drift against the plan, runs blind scenarios for L work and parks scope creep. | `<pitch id> [--timebox 2h]` |
| `/garage:test` | Run the test suite and own the result. Detects the test command, runs it, investigates every failure and fixes it, with no "pre-existing failure" excuses. Large suites are split across parallel testers. | `[path | pattern | leave empty for all]` |
| `/garage:tidy` | Behavior-preserving cleanup. Improves structure, naming and duplication in small steps with tests green after each step, and stops at the first red. | `<file, folder or smell to fix>` |

## Verify

| Command | What it does | Argument |
|---|---|---|
| `/garage:break` | Adversarial testing. The gremlin agent attacks recent changes with hostile inputs, edge cases and bad state, and proves each finding with a failing test. | `[pitch id | path | leave empty for the current git diff]` |
| `/garage:audit` | Adaptive parallel review before merge. Security, quality and tests are always reviewed; concurrency, dependencies, UI and infrastructure specialists join automatically when the diff calls for them. Returns one ranked verdict. | `[base branch, default main]` |

## Ship

| Command | What it does | Argument |
|---|---|---|
| `/garage:pr` | Prepare a pull request from your branch. Writes a clear title and description with the why, evidence, risks and a reviewer checklist. Never opens the PR without confirmation. | `[base branch, default main]` |
| `/garage:launch` | Pre-release checklist and release writing. Verifies tests, docs and version, drafts the changelog and release notes, and never tags or pushes without confirmation. | `[patch | minor | major]` |
| `/garage:docs` | Generate or synchronize documentation with the code. Creates README, API docs or architecture notes, and finds stale docs that no longer match reality. | `[readme | api | arch | sync] [path]` |

## Maintain

| Command | What it does | Argument |
|---|---|---|
| `/garage:firefight` | Fix a bug or incident by root cause. Investigators work in parallel with competing hypotheses and try to disprove each other, then the surviving cause gets a minimal fix and a regression test. | `<symptom, error message or failing test>` |
| `/garage:retro` | Short retrospective that turns what just happened into durable lessons. Writes actionable "when X, do Y" rules to .garage/lessons.md that every other command reads. | `[pitch id | leave empty for recent work]` |
| `/garage:standup` | Instant status report from git history and .garage state. What shipped, what is in progress, what is blocked, and what to do next. | `` |
